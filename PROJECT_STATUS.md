## Мета
Android OSINT-бібліотека українською на Kotlin з офлайн-уроками, локальним сервером на Android (Termux), вебадмінкою та RSS-імпортом. Репозиторій: https://github.com/MrKanzo/Os1n7.

## Що вже реально перевірено на телефоні
- Android OS1N7 v0.4.2 має кнопку «🌐 Серверна бібліотека», читає HTTP API, відкриває тексти та має кнопку «Синхронізувати».
- Офлайн-читальня містить 18 уроків із пошуком, категоріями, закладками (зберегти).
- Termux + Python на **тому самому Android** обслуговує http://127.0.0.1:8765.
- GET / повертає статус і кількість; GET /api/articles повертає JSON {"version":1,"articles":[{"id","title","category","summary","content"},...]}.
- Спочатку було 4 статті; через редагування сервера додали «Зворотний пошук зображень» (5) без перевстановлення APK.
- Встановлено локальну адмінпанель /admin, додано Test6 (6) через Chrome, APK не оновлювався.
- Встановлено RSS-оновлення; Bellingcat дав 10 кандидатів на ручне схвалення; один схвалений матеріал з'явився в Android (7). Це підтверджено скриншотами користувача.
- **Важливо:** RSS-опис є коротким уривком із рекламними фразами, НЕ повним текстом статті. Потрібні очищення, переклад/українська анотація, відкриття першоджерела.

- Резервні копії, які повинні були створити оновлення: `server_before_rss.py` і попередня резервна копія від admin upgrade; перевірити на пристрої.

- RSS-черга: на скриншоті URL починався з `/admin/dis...`; уточнити точний маршрут у серверному коді.

## Запуск сервера після перерви
1. Відкрити Termux; перевірити наявність файлів: `ls ~/storage/shared/os1n7-server-test/os1n7-server/`.
2. Запустити: `python ~/storage/shared/os1n7-server-test/os1n7-server/server.py`.
3. В Chrome відкрити http://127.0.0.1:8765/api/articles — має бути JSON.
4. В OS1N7 → «Серверна бібліотека» → «Синхронізувати».
5. Адмінпанель: http://127.0.0.1:8765/admin; для змін потрібен приватний ключ адміністратора. **Не записувати ключ або пароль у GitHub/чат.**
6. Для зупинки сервера: CTRL+C у Termux.

## Важливі незакриті технічні питання
1. **Підпис APK**: GitHub Actions debug builds можуть мати різні підписи, Android повідомляв про конфлікт. Налаштувати постійний release keystore і GitHub Secrets: OS1N7_KEYSTORE_BASE64, OS1N7_STORE_PASSWORD, OS1N7_KEY_ALIAS, OS1N7_KEY_PASSWORD. Keystore можна створити на Android через Termux + keytool. Перший перехід на новий підпис вимагатиме видалення старої тестової програми, якщо оригінальний ключ недоступний. Забезпечити надійний резервний бекап keystore.
2. **Оновлювач APK**: може вибирати перший .apk у GitHub Release, а не обов'язково підписаний; пріоритезувати app-release.apk, не змішувати debug та release, перевірити логіку версій.
3. **Вигляд серверної бібліотеки**: зараз світло-сірі великі кнопки, білі діалоги, довгі RSS-описи. Зробити темні картки, короткі анотації, повноцінний екран читання.
4. **RSS**: очищення HTML/рекламних вставок, редагування перед схваленням, українські заголовки/анотації, джерело та дата, категорії, дублікати, відкриття оригіналу. Не копіювати повні сторонні тексти без дозволу.
5. **Клієнт**: пошук, фільтри, закладки, офлайн-кеш, об'єднання офлайн-уроків і серверного каталогу. Відокремити «Навчання / Інструменти» від «Новини / Розслідування».
6. **Сервер**: редагування/видалення статей, імпорт кількох перевірених RSS, бекап JSON. Тримати адмінку тільки на localhost, не відкривати в інтернет без TLS/автентифікації.
7. **Збереження на GitHub**: серверний `server.py`, `articles.json` і застосовані upgrade-файли фізично знаходяться на телефоні, не синхронізуються з GitHub автоматично. Потрібно окремо завантажити їх у репозиторій (без секретів) або створити безпечний експорт. Наявні 7 статей НЕ слід вважати вже скопійованими до GitHub.

## Безпека
- Адмінключ зберігати лише локально/у захищеному сховищі; не комітити.
- `127.0.0.1` — локальний доступ на одному телефоні; для інших пристроїв потрібна окрема захищена конфігурація.
- При очищенні даних Termux, видаленні папки сервера чи скиданні телефона статті можуть зникнути. Потрібен бекап.
